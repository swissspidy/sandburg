# ADR 0011: Svelte, Solid, Preact and Lit in the esbuild adapter

- Status: Accepted
- Date: 2026-09-30

## Context

After React and Vue (ADRs 0007, 0009), the other client frameworks that
generated apps use most are Svelte, Solid, Preact and Lit. Each has an
official create-vite template, which is what generators start from. Every
framework except Lit needs its Vite plugin's compile step.

## Decision

As with Vue and Tailwind, the build loads the app's own compiler into the
page. It bundles the compiler with esbuild-wasm from the app's node_modules
and imports it. No framework code runs on the host.

- **Svelte** (`@sveltejs/vite-plugin-svelte`). `svelte/compiler` compiles
  `.svelte` components for the client in dev mode, with CSS injected.
  `compileModule` handles `.svelte.js` and `.svelte.ts` rune modules, whose
  types are stripped first. Svelte 5 reads `<script lang="ts">` itself.
  `<style lang="scss|less|…">` needs a preprocessor, so it is unsupported.
- **Solid** (`vite-plugin-solid`). Project `.jsx`/`.tsx` files go through the
  app's `babel-preset-solid` with its `@babel/core`, after esbuild strips the
  types and keeps the JSX. Solid's `browser`/`development` export conditions
  select its dev build.
- **Preact** (`@preact/preset-vite`). JSX uses `jsxImportSource: 'preact'`,
  and `react`, `react-dom` and their JSX runtimes are aliased to
  `preact/compat` and `preact/jsx-runtime`. The resolver gained package
  aliases for this.
- **Lit** needs no plugin. It needs the project's TypeScript settings
  (`experimentalDecorators`, `useDefineForClassFields`). esbuild cannot read
  tsconfig.json in the browser, so the build now passes the relevant
  compiler options as `tsconfigRaw`. This applies to every project.

Fixes found along the way:
- **Resolver.** Deep imports into packages without `exports`
  (`caniuse-lite/dist/unpacker/agents`) resolved outside the package. Package
  `imports` (`#client/constants`) are now supported, and a leading `#` is
  no longer taken for a URL fragment.
- **Compilers bundled into the page** get small CommonJS `path`, `url`,
  `assert` and `util` modules and a `process` global. Babel needs them.
  App bundles still get empty Node built-ins, as in Vite.
- **Unsupported features.** A feature the build does not run (a style
  preprocessor, or `<style module>`/`src=` blocks in Vue) is now classified
  as `runtime-unsupported` instead of `app-bug`.

## Consequences

- Four new fixtures, generated by `create-vite` (`svelte-ts`, `solid-ts`,
  `preact-ts`, `lit-ts`), pass their checks in 2.5–6 s each. The Svelte one
  adds a rune store module and `{#each}`/`bind:`/`$derived`; the Solid one
  adds `<For>`.
- A Svelte syntax error is an app bug with `file:line:column`, and Svelte
  with `<style lang="scss">` is unsupported.
- Meta-frameworks (SvelteKit, Astro, Nuxt, React Router, SolidStart,
  TanStack Start, Qwik City) need server rendering and Vite's own dev
  server, so the esbuild adapter cannot cover them. They all run on Vite 8,
  whose native parts (rolldown, lightningcss, and Astro's compiler) have
  WebAssembly builds. Running real Vite in the node runtime is the next step.
