# Fidelity studies

almostnode, measured in v1 and v2, was removed in [ADR 0013](../adr/0013-runtime-consolidation.md); v3 measures its replacement (`--runtime auto`), and v4 the node runtime alone ([ADR 0014](../adr/0014-node-runtime-only.md)); v5 and v6 measure the speed work since.

Each study runs the same 100 apps (`corpus/`, generated by
`scripts/corpus/generate.ts` with seed 1) in the browser runtime and in the
Docker reference, with identical checks. For the method and the caveats, see
[ADR 0004](../adr/0004-docker-reference-and-fidelity-study.md).

| Study | Browser runtime | Agreement | Browser vs truth | Reference vs truth | Machine time per app (browser / Docker) |
|---|---|---|---|---|---|
| [v1](v1-almostnode-vs-docker.md) | almostnode 0.2.14, adapter as of milestone 3 | 77.0% | 80.0% | 97.0% | 1.7 s / 5.2 s |
| [v2](v2-almostnode-vs-docker.md) | almostnode 0.2.14, adapter fixed after v1 | 97.0% | 100.0% | 97.0% | 1.8 s / 4.9 s |
| [v3](v3-auto-vs-truth.md) | `--runtime auto` (esbuild for Vite, node for Next.js) | not measured (no Docker) | 97.0% | (97.0% in v1/v2) | see report |
| [v4](v4-node-vs-truth.md) | the node runtime for every app (real Vite, real `next dev`) | not measured (no Docker) | 97.0% | (97.0% in v1/v2) | see report |
| [v5](v5-node-vs-truth.md) | the node runtime after the cold-start work (ADR 0014) | not measured (no Docker) | 97.0% | (97.0% in v1/v2) | see report |
| [v6](v6-node-vs-truth.md) | v5 plus fail-fast checks, Vite seeds and warm-ups (ADR 0016) | not measured (no Docker) | 97.0% | (97.0% in v1/v2) | see report |

Caveats:
- The corpus is synthetic, and v2's adapter fixes were made against this
  same corpus. Treat v1 as the drop-in baseline and v2 as an upper bound
  until a fresh, LLM-generated corpus is run.
- The reference's three "misses" against ground truth are phantom
  dependencies (`nanoid` is hoisted by npm), not reference bugs. The
  corpus's labels were wrong for those three apps.

To reproduce, generate the corpus first:

```sh
node scripts/corpus/generate.ts corpus 100 1
```

v1 and v2 (almostnode, which no longer exists, against the Docker reference):

```sh
node bin/sandburg.js compare corpus --reference docker --parallel 4 --report docs/fidelity/vN-almostnode-vs-docker
```

v3 and v4 (against ground truth; v3's `--runtime auto` no longer exists): run the batch, then compare each run's
status with the app's `meta.expected` (`corpus/<app>/meta.json`):

```sh
mkdir -p .sandburg/study && node bin/sandburg.js batch corpus --parallel 3 --out .sandburg/study --json > .sandburg/study/batch.json
```

With Docker, `compare corpus --reference docker` also reports agreement with the reference.
