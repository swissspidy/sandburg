A project or checks file that does not load ends its run as an `error` result (`app-bug`, rule `project-load` or `checks-load`) instead of rejecting the whole batch, so the other runs keep their results and `summary.json` is written. The CLI loads the project and checks file it is given before the browser starts: a path that is not there, or a checks file that does not import, prints one `error:` line and exits 2 (no stack trace, no empty run directory), and `--runtime` with an unknown name or an unknown command (`unknown command: x`) exits 64. `dist/`, `build/`, `.next/`, `.turbo/` and `.cache/` are left out of a project at its root only, so `src/build/x.js` is part of it; `node_modules/`, `.git/` and `.sandburg/` still are at any depth. `sandburg open` keeps its window open when a phase before the checks fails. Functional checks whose names make the same id (`Add item`, `add-item`) get `-2`, `-3`, …, and a name with no letter a-z or digit is `check-<n>`. `compare` exits 2 when nothing could be compared; `--reference` and `--report` are in `--help`, and the unused `--corpus` option is gone. API: `RunOptions.seed` is no longer public (seed runs are the session's own), the adapter contract (`AdapterDescriptor`, `HostRequest`, `HostResponse`, `HostInstallOptions`, `AdapterErrorCode`) is no longer exported by name, and `ClassifyInput` has `setupError`.
