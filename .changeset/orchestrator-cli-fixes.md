"sandburg": minor

A project or checks file that does not load ends its run as an `error` result (rule `project-load` or `checks-load`; `app-bug` for a project file that is there but broken, else `unknown`) instead of rejecting the whole batch, so the other runs keep their results and `summary.json` is written; `compare` excludes such pairs. A run whose checks file is broken still stores its project's snapshot; one whose project did not load has the snapshot id `000…0` (64 zeros), which no stored tree has, and a snapshot id that is not stored fails with `snapshot <id>: not found`. `run` and `open` load the project and checks file they are given before the browser starts (a batch's `--checks` loads only in the runs that use it): a path that is not there, or a checks file that does not import, prints one `error:` line and exits 2 (no stack trace, no empty run directory), and `--runtime` with an unknown name or an unknown command (`unknown command: x`) exits 64. `dist/` and `build/` are left out of a project at its root only, so `src/build/x.js` and a monorepo's `packages/*/dist/` are now part of it; `node_modules/`, `.git/`, `.sandburg/`, `.next/`, `.turbo/` and `.cache/` still are at any depth. `sandburg open` keeps its window open when a phase before the checks fails. Functional checks whose names make the same id (`Add item`, `add-item`) get `-2`, `-3`, …, and a name with no letter a-z or digit is `check-<n>`. `compare` exits 2 when nothing could be compared; `--reference` and `--report` are in `--help`, and the unused `--corpus` option is gone. API: `RunOptions.seed` is no longer public (seed runs are the session's own), the adapter contract's internals (`HostRequest`, `HostResponse`, `HostInstallOptions`, `AdapterErrorCode`) are no longer exported by name (`AdapterDescriptor`, what `getAdapter` returns, still is), and `ClassifyInput` has `setupError`.
