A process that keeps running while `.sandburg` is removed (a test runner, a server) no longer trusts installs that are gone. A later `Session` failed with `the dev script runs "vite", which no installed package provides`, because the host remembered each finished install for the life of the process. An install's `.sandburg-complete` now holds a random record id, and an install that is asked for again reads it: when the record is gone or is another one (the install was removed, or removed and made again), the install is made again, and what the host kept of it is dropped (its file index, transforms in memory, package types, read-ahead listings, preload lists and bundles). A record that cannot be read for a moment (EMFILE on a busy host) is not taken for a removed one. Records written by earlier versions, without an id, are told by their stat, so existing installs are used as they are. Side installs are checked the same way. Compiles kept in memory whose file was removed are written again (each is still the right output for its code), and a seed run whose stored cache was removed runs again (#117).
