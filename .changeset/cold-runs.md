"sandburg": patch

Faster cold runs (an app or install never run on the machine). npm's resolution reads packuments trimmed of what it never uses (Vite's licence texts, readmes, `exports`, maintainers, legacy signatures), kept in npm's own cache beside the packuments they come from and checked against them; whether a napi-rs package's WebAssembly binding exists is asked in the resolver's worker instead of an `npm view` process each; WebAssembly builds and bindings are hard-linked into installs instead of copied. The host's transforms of installed files read and answer without waiting on promise-based file system calls, and check ES modules for wrapper clashes more cheaply. A runtime that reads a raw installed file missing from its preload bundle gets the files after it in its directory with it (a bundler's first pre-bundle read thousands, one request each), and, for an install never run, a transformed module comes with the modules it requires that the host has transformed already; only files a runtime reads are recorded for later preload bundles. A session starts esbuild's services while it opens. `scripts/profile.ts --cold` profiles a first run, and `scripts/bench.ts` takes directories such as `corpus/012-vite-react` as fixtures.
